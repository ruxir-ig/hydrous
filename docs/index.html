Hydrous

AGPL-3.0 PythonTypeScript SDKHydraDB optional

mem0’s API, none of mem0’s amnesia — append-only bi-temporal memory with provenance, abstention, and graph retrieval, on a single engine instead of Qdrant+Neo4j+Postgres glue.

Pitch · Quickstart · API · Comparison · Demos · Architecture

The pitch

mem0 OSSHydrous
Flat strings; a newer fact is a new row, the old one still searched as current Bi-temporal facts; supersession closes valid_to (PATCH, stable id); old versions stay retrievable
Known junk-extraction problem (“98% junk”, issue #4573) Quality gate: every fact scored (confidence), junk REJECTed before storage, score kept in metadata
Re-adding search results duplicates memory Feedback-loop prevention: search results tagged, re-add is a NOOP
search(reference_date=...) raises “platform-only” reference_date works: true as-of time travel
chat() raises NotImplementedError chat() retrieves + reads and abstains verbatim when evidence is missing — no hallucination
No multi-hopHydraDB graph_context lanes merged into evidence
No RAG corpusMulti-corpus type="memory"|"knowledge" with per-scope collections weighting — RAG + memory in one database
No migration pathhydra-mem import-mem0 replays a get_all export, created_at → recorded_at

Quickstart

uv sync                     # python: hydrous engine + hydra_mem compat facade
cp .env.example .env        # add your LLM key (or use MockLLM / --mock)

# mem0 drop-in, local store:
uv run python -c "
from hydra_mem import Memory
m = Memory()
m.add('I love hiking on weekends', user_id='alice')
print(m.search('hiking', filters={'user_id': 'alice'}))
"

# HTTP bridge (the TS SDK's backend) + 4 positioning demos (offline):
.venv/bin/hydra-mem serve --mock --port 8765   # in another terminal
.venv/bin/hydra-mem demo

API

Python — mem0-compatible

from hydra_mem import Memory          # or AsyncMemory

m = Memory(store="local")             # or Memory(store="hydradb", ...)
m.add(msg, user_id=..., infer=False)  # raw fast path, no LLM
m.search(q, filters={"user_id": "alice"}, reference_date="2024-01-01")
m.get(memory_id)          # item | None (mem0 parity)
m.history(memory_id)      # supersession chain (mem0 field names)
m.update(memory_id, text=...); m.delete(memory_id); m.reset()
m.chat(q, filters=...)    # abstains verbatim when evidence is missing
m.add_knowledge(doc, user_id=...)        # RAG corpus (extension)
m.search(q, filters=..., collections=[{"name": "knowledge", "weight": 0.5}])

TypeScript — hydrous-ts

import { Memory } from "hydrous-ts";
const m = new Memory({ baseUrl: "http://127.0.0.1:8765" });
await m.add("I love hiking", { user_id: "alice" });
const hits = await m.search("hiking", { filters: { user_id: "alice" } });

HTTP — hydra-mem serve

POST /add /search /get_all /update /delete /delete_all /reset /chat / add_knowledge /import-mem0 · GET /get/{id} /history/{id} · POST /webhooks/hydradb/indexing (webhook-driven indexing) · GET /health

Demos mem0 structurally cannot do

1 · “before”

Superseded facts answer what laptop did I use before the MacBook? — old versions stay retrievable.

2 · time travel

reference_date="2024-01-01" returns the state valid then. mem0 OSS raises “platform-only”.

3 · abstention

No evidence → the exact abstention string, never a hallucination.

4 · multi-hop graph

HydraDB graph_context lanes surface scored path contexts — retrieval across fact chains.
